## Project overview

This academic project demonstrates how electricity-consumption history can be analysed to screen for unusual patterns. The proposed system design uses smart meters, a transformer-level meter, an IoT gateway, a data store and a Python analysis layer. The supplied program is an **offline Python prototype**: it reads a labelled CSV file or generates artificial demonstration data. It is not connected to a live smart meter, MQTT broker, cloud service or electricity utility.

The program calculates six consumption features and trains a Random Forest classifier. It creates an overall feature-importance report and simple rule-based explanations for individual records.

> **Important:** The demo data and its scores are synthetic and only demonstrate that the program runs. They are not evidence of real-world electricity-theft detection accuracy. A model alert is not proof of theft and requires authorised human verification.

## Run the synthetic demonstration

Open a terminal or Command Prompt in the repository folder and run:

```bash
python -m pip install -r requirements.txt
python theft_detection_iot_simple.py --demo
```

The program creates an `outputs_simple/` folder in the current working directory. It writes customer predictions, evaluation metrics, a confusion matrix and feature-importance files to that folder.

## Run with a labelled CSV file

```bash
python theft_detection_iot_simple.py --data path/to/your_dataset.csv
```

The input CSV must use a **wide format**: one customer per row, a label column (for example `FLAG`, `label` or `target`), and at least five numeric consumption-reading columns in chronological order. Common customer-ID columns are recognised automatically. The labels must identify normal records as `0` and theft-labelled records as `1`, or use common equivalent text labels described in the source code.

The SGCC dataset itself is not included in this repository. Obtain it only from an appropriate research source, check its documentation and terms, and prepare it in the input format expected by the program before running the real-data mode. Do not upload confidential or personally identifying consumer data to a public repository.

## Features calculated

1. `average_daily_kwh` – average of the available readings.
2. `usage_variation` – standard deviation of the readings.
3. `near_zero_percent` – percentage of readings at or below 0.05 kWh.
4. `early_average_kwh` – average of the first comparison window.
5. `recent_average_kwh` – average of the latest comparison window.
6. `recent_change_percent` – percentage change from the early average to the recent average.

## Model and explanation

The program uses `RandomForestClassifier` with 150 trees, balanced class weights and a fixed random seed. It reports accuracy, precision, recall and F1-score. It also saves model-level feature importance and short rule-based reason statements. These reasons are screening aids; they do not constitute proof of an offence or a full causal explanation of a model prediction.
